# CA AutoConfig v0.2.6-alpha.1

This alpha replaces the optional script-based SYSTEM GPU action with a compiled, transactional helper. The default desktop install remains an unprivileged, read-only HUD and does not install or run the helper.

## What changed

- `CAGpuHelper.exe` accepts only two operation shapes: a strict UUID-pinned Apply command installed by an administrator, or argument-free Reset.
- NVIDIA commands use the fixed System32 executable and structured process arguments—never a shell.
- Apply preflights every target before the first write, refuses power above the vendor-reported default, and atomically records exact pre-change power caps.
- Reset restores those exact values plus vendor-managed graphics clocks. Apply and Reset both attempt reverse recovery after partial failure.
- Separate fixed SYSTEM tasks let the configured user run the reviewed Apply/Reset operations without permission to rewrite their commands.
- The installer pins the helper SHA-256 across UAC, rejects reparse-point sources/install directories, and refuses legacy migration when the original power values are unknown.
- Manual Apply and Rollback require explicit confirmation. The standard-user control panel has no direct GPU mutation or self-elevation path.

## Install

The ordinary install is unchanged:

```powershell
.\Install-DesktopApp.ps1
```

That installs only the HUD and control panel. Optional GPU limits still require explicit board-specific values and acknowledgement:

```powershell
.\Install-GpuLimits.ps1 -GpuIndexList '0,1' -MaxGraphicsClockMHz 1700 -PowerLimitWatts 280 -AcceptHardwareRisk
```

The example is not a universal recommendation. Use limits supported by your exact cards and validate both workload and idle behavior.

## Existing script-helper installations

Do not let the new helper learn an already-limited value as the original value. First use the previous installed control panel to reset the active legacy profile, confirm the state reports `reset`, and only then run the new installer. The installer fails closed if it detects an applied legacy profile without an exact protected rollback record.

## Verification completed

- Eight deterministic compiled-helper tests with a fake NVIDIA runner: strict parser, injection rejection, all-target preflight, Apply rollback, exact Reset, failed-Reset recovery, corrupt-record rejection, and rollback-record mismatch refusal.
- Policy tests in PowerShell 7 and Windows PowerShell 5.1 for ACL/task intent, hash pinning, confirmation, and absence of direct mutation/elevation in the standard-user control panel.
- Self-contained desktop smoke mode confirmed no hardware writes.

No live GPU migration or reset was performed while preparing this release. The binaries are not yet code-signed, and clean-machine/sleep/driver-reset recovery still needs independent testing before `v1.0`.
