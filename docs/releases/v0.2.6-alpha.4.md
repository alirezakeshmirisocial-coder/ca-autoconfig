# CA AutoConfig v0.2.6-alpha.4

This is the current self-contained Windows/NVIDIA HUD alpha. It includes the tiny lock/edit control, click-through locked mode, visual monitor selection, a user-defined global shortcut, CPU/RAM/storage telemetry, and per-GPU CUDA/SM, VRAM, watts/cap, temperature, and clock data. The default install is standard-user, camera-free, and hardware-write-free.

This release is unsigned. Read the [two-minute quick start](https://github.com/alirezakeshmirisocial-coder/ca-autoconfig/blob/main/docs/QUICKSTART.md) before running it.

## Install the default HUD

Download these exact assets into the same directory:

- [CA-AutoConfig-Desktop-v0.2.6-alpha.4-win-x64.zip](https://github.com/alirezakeshmirisocial-coder/ca-autoconfig/releases/download/v0.2.6-alpha.4/CA-AutoConfig-Desktop-v0.2.6-alpha.4-win-x64.zip)
- [CA-AutoConfig-Desktop-v0.2.6-alpha.4-win-x64.sha256](https://github.com/alirezakeshmirisocial-coder/ca-autoconfig/releases/download/v0.2.6-alpha.4/CA-AutoConfig-Desktop-v0.2.6-alpha.4-win-x64.sha256)
- [Verify-DesktopPackage.ps1](https://github.com/alirezakeshmirisocial-coder/ca-autoconfig/releases/download/v0.2.6-alpha.4/Verify-DesktopPackage.ps1)

Before extraction, compare the ZIP's SHA-256 with the published value below, then run the offline verifier:

```powershell
.\Verify-DesktopPackage.ps1 -PackagePath .\CA-AutoConfig-Desktop-v0.2.6-alpha.4-win-x64.zip -ExpectedVersion 0.2.6-alpha.4
```

Published candidate ZIP SHA-256: `0a71a120139bf10e36bdad1c816cbd07b9fbcac9651ef498ba214862b32f3b6d`.

After verification, extract the ZIP and run `CAAutoConfig.exe` directly for a portable, standard-user trial. This does not create a startup task or shortcut.

When you are ready to keep it, exit the portable trial from its tray icon and run:

```powershell
.\Install-DesktopApp.ps1
```

The installer creates the least-privilege `CA System Overlay` task for Logon and SessionUnlock and a desktop shortcut. It does not install the presence experiment or privileged GPU helper. Click the tiny lock control or press `Ctrl+Alt+L`, choose a display in Settings, place the HUD, customize the shortcut and opacity, then lock it again.

To remove the installed HUD and task from the extracted release directory:

```powershell
.\Uninstall-SystemOverlay.ps1 -RemoveFiles
```

Local preferences remain available for a future reinstall.

## Windows GPU research additions

This alpha also makes the Windows GPU fallback research reproducible without enabling it in the HUD and packages the offline Windows Sandbox install/uninstall harness added after alpha.3.

## Windows GPU research probe

After verification and extraction, write one local sanitized report:

```powershell
.\CAAutoConfig.exe --windows-gpu-probe-result .\windows-gpu-probe.json
```

The one-shot probe joins DXGI hardware adapters to Windows formatted GPU engine and dedicated-memory counters. It uses the adapter LUID only as an in-memory correlation key, filters adapters carrying the official DXGI software flag, and emits only the capture time, status, reason codes, adapter index/name, busiest-engine load, dedicated-memory use/capacity, and VRAM percentage.

The report never contains LUIDs, PIDs, PNP identifiers, usernames, machine names, or paths. The probe makes no network request, requests no elevation, changes no hardware, and always reports `canUseInHud=false`.

## Evidence and boundaries

- Seven capability fixtures pass in PowerShell 7 and Windows PowerShell 5.1.
- Fourteen compiled mapping/provider/report cases pass without hardware access.
- A self-contained standard-user run on the maintainer's dual-RTX-3090 Windows 10 system mapped both hardware adapters and excluded the DXGI-flagged software adapter.
- The 47-file candidate verified in both PowerShell runtimes as 280,768,470 uncompressed bytes without extraction or execution.
- The existing desktop smoke path remains hardware-write-free.
- The clean-machine harness has five deterministic preparation tests in both PowerShell runtimes, but no real Windows Sandbox result exists yet.

This release does not add an AMD/Intel HUD provider, background WDDM polling, driver-reset recovery, a universal GPU limit, code signing, or active CI. Cross-hardware reports must retain failures, and raw identifiers should never be attached to issues.
