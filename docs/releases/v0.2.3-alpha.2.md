# CA AutoConfig v0.2.3-alpha.2

This alpha shortens the path from “something looks wrong on my workstation” to a useful, privacy-checked hardware report.

## What changed

- Added **Copy diagnostics** to Settings with inline success feedback and a recoverable clipboard-busy error.
- Included app/Windows version, architecture, shortcut, selected display, display topology and DPI scale, profile state, and GPU telemetry/advisor values.
- Excluded usernames, machine names, GPU UUIDs, local paths, prompts, outputs, workflows, and image content; UUID/path patterns are defensively redacted and covered by a deterministic test.
- Added a public evidence-tiered hardware matrix that distinguishes maintainer-live checks, deterministic fixtures, unsupported surfaces, and external reproductions. External coverage is intentionally still zero.
- Fixed issue-form labels and made failure/incomplete-run retention compatible with hardware submissions.
- Opened a 20-seat focused alpha intake across install/HUD, multi-monitor, and local-AI workload cohorts. No star is requested or required.
- Regenerated the demo from CA AutoConfig windows only and corrected the maintainer topology using DPI-aware diagnostics.

## Install

Download `CA-AutoConfig-Desktop-v0.2.3-alpha.2-win-x64.zip` and its `.sha256` file, verify the checksum, extract it, and run:

```powershell
.\Install-DesktopApp.ps1
```

The installer runs the HUD as the standard user at Logon and SessionUnlock. It does not install the optional camera experiment or apply GPU settings. The ZIP remains unsigned while signing and clean-machine upgrade coverage are open release gates.

## Verification

- Shared HUD source compile, settings round-trip, diagnostic redaction, 13 deterministic NVIDIA cases, and live query-only dual-GPU telemetry.
- Framework-dependent and self-contained .NET 8 desktop startup/persistence smoke tests.
- End-to-end Settings-button clipboard test on the maintainer mixed-DPI three-display topology.
- Application-window-only demo capture; no desktop pixels recorded; locked state restored.

The Ollama, llama.cpp, and ComfyUI adapters are unchanged from `v0.2.3-alpha.1`. No real workload power curve or external hardware reproduction is claimed by this release.
