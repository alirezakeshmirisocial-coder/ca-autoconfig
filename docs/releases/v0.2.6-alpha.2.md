# CA AutoConfig v0.2.6-alpha.2

This alpha adds a privacy-safe GPU limit plan before the optional elevated workflow. The default desktop install remains an unprivileged, read-only HUD and does not install or run the helper.

## What changed

- `Get-GpuLimitPlan.ps1` queries only the explicitly selected cards and reports current draw/cap, vendor default/minimum/maximum power limits, current graphics clock, vendor maximum graphics clock, and installed-profile migration readiness.
- The plan contains no NVIDIA write flags, elevation path, or GPU UUID output. It can show a shared no-raise power starting point, but deliberately never invents a workload-independent clock suggestion.
- A proposed profile is rejected before UAC if it is incomplete, outside any selected board's range or default, above a vendor maximum clock, would raise a current cap without a separate acknowledgement, or would overwrite a legacy/installed profile without a safe reset.
- The compiled helper independently enforces the vendor-reported maximum graphics clock and requires the fixed task's exact `--allow-power-increase` flag before any current power cap can rise.
- The installer reruns the plan before elevation and carries an explicit power-increase acknowledgement into the hash-pinned, fixed SYSTEM task.

## Inspect before installing

```powershell
.\Get-GpuLimitPlan.ps1 -GpuIndexList '0,1' -PowerLimitWatts 280 -MaxGraphicsClockMHz 1700
```

The numbers above are an example from one maintainer workstation, not a universal recommendation. Review the output for your exact boards. If the plan reports `legacy-reset-required` or another migration reason, use the currently installed rollback path first and do not bypass the gate.

The optional installer still requires explicit values and hardware-risk acknowledgement:

```powershell
.\Install-GpuLimits.ps1 -GpuIndexList '0,1' -MaxGraphicsClockMHz 1700 -PowerLimitWatts 280 -AcceptHardwareRisk
```

If—and only if—the proposal intentionally raises a current power cap, also pass `-AcknowledgePowerIncrease` after reviewing that change.

## Verification completed

- Ten deterministic compiled-helper cases with a fake NVIDIA runner, including vendor max-clock rejection and explicit acknowledgement before a current-cap increase.
- Seven deterministic planner cases covering inventory-only behavior, shared power starting points, per-board range and clock validation, acknowledgement, complete profiles, and absence of mutation/elevation.
- Planner and helper policy suites passed in PowerShell 7 and Windows PowerShell 5.1.
- A live query-only plan on the maintainer's dual-GPU system separated a valid proposed profile from an unsafe legacy migration and failed closed with `legacy-reset-required`.

No live GPU reset, migration, or mutation was performed while preparing this release. The binaries are not yet code-signed, and clean-machine, sleep, and driver-reset recovery still need independent testing before `v1.0`.
